## Key concepts

### Backup vs Shadow Copy vs Proxmox backup

| | Shadow Copy | Windows Server Backup | Proxmox backup |
| --- | --- | --- | --- |
| What | Snapshots of a volume | Files, folders or the whole server | The whole VM |
| Speed to restore | Seconds | Minutes | Minutes to hours |
| Protects against | Deleted or overwritten files | Data loss, if stored on another disk | The whole server failing |
| Who restores | The user (Previous Versions) | IT | IT |

- **A backup you haven't restored isn't a backup.** Always test a restore.
- **A backup on the same disk as the data is not a real backup.** If the disk fails, both are lost. This is a **single point of failure (SPOF)**.
- **3-2-1 rule:** 3 copies of the data, on 2 different types of storage, with 1 copy off-site.
- Shadow copies are stored on the same volume by default, so they are **not** a replacement for backups. Old snapshots are deleted automatically when space runs out (maximum 64 per volume).
- Backups and shadow copies should be **scheduled**, not run by hand.

## Commands

```powershell
# Windows Server Backup
wbadmin get versions
wbadmin start backup -backupTarget:E: -include:D:\Shares -quiet

# Volume Shadow Copy
vssadmin list shadows
vssadmin list shadowstorage
vssadmin create shadow /for=D:
```

(Drive letters are examples: E: = backup volume, D: = data volume.)
