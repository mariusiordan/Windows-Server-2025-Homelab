## Problems and how I solved them

| Problem | Cause | Fix |
|---|---|---|
| Couldn't find *Read/Write lockoutTime* in the wizard | Long property list; needs **User objects** + **Property-specific** only | Scrolled to "L" — or use Security → Advanced → Add |
| Emma's account was already unlocked when I checked | **Lockout duration 15 min** — it unlocked by itself | Locked it again to practise the manual unlock |
| `LockedOut: False` but `lockoutTime` was a big number | After an automatic unlock, AD keeps the old time | `LockedOut` is the truth; `lockoutTime` goes to 0 only after a manual unlock or good login |
| `lockoutTime` converted to **9:37 AM** instead of 5:37 PM | The **old PowerShell window** still used Pacific time | Opened a new window → 5:37 PM ✅ |

## Key concepts

- A lockout threshold of **0** means unlimited password guessing — not acceptable for a bank.
- A **short** lockout duration stops attackers locking out everyone on purpose.
- **Delegation:** give the Service Desk exactly what it needs (reset + unlock on staff), nothing more.
- **Identity before unlock:** call back on the number **from AD**, or ask the manager. Approval isn't needed to restore existing access — identity always is.
- A user who can't log in can't create a ticket: the Service Desk logs it for them.
- **Run as different user:** work as a normal user, open only the admin tool with the `adm-` account.
